# Production Discipline

## Weekly Scope Rule

Each week is limited to 1–3 meaningful tasks.
If more fits, great. If not, that is enough.
Over-scoping is not allowed.

## Single-System Rule

Only one core gameplay system is actively being built at a time.
No parallel system hopping unless the current system is blocked.

## Rewrite Rule

Major rewrites require a written justification explaining:
- What problem is being solved
- Why iteration isn’t enough
- What measurable improvement is expected

## Bug Tracking Rule

Bugs are tracked separately from feature development.
Bug-fixing sessions are scheduled intentionally.

All issues must be labeled as:
- bug
- feature

Bug issues are not mixed into feature planning unless explicitly scheduled.

## Done Definition

A task is only marked Done when:
- It compiles
- It runs
- It has been manually tested once

## Version Format

*** Use ***: MAJOR.MINOR.PATCH
*** Start At ***: 0.1.0

*Meaning*
0 = Pre-release
1 = First playable milestone
0 = No patches yet

## Build Naming Convention

ABRV_0.1.0_YYYYMMDD

*Example*
HH_0.1.0_20260225
